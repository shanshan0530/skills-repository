# Codex 前端工程化工作流 ｜ 别让 AI 猜审美

## 功能描述

用 Codex 写前端时，只给模糊需求会出廉价 AI 模板感，根源是让 AI 自己猜审美。正确做法是先定产品约束，出视觉方向稿，拆成可落地的设计规格，再给 Codex 写清运行边界的完整任务包，最后用 Playwright 对照规范反复修正。

## 核心原则

**别让 Codex 猜审美。**

你给的规格越详尽，前端还原效果越好。

## 正确工作流

1. **先定产品约束**
   - 明确业务目标、目标用户、交互边界、性能要求
   - 输出产品需求文档（PRD）与技术约束清单

2. **用 GPT Image 出多版视觉方向稿**
   - 批量生成 3–5 版视觉方向（Hero、组件、移动端/桌面端）
   - 从中选 1–2 版作为主方向，冻结风格调性

3. **拆成标准化可落地设计规格**
   - 色板、字体、间距、圆角、阴影、动效曲线
   - 组件级 Token（Button、Card、Input 等）
   - 响应式断点与栅格规则

4. **给 Codex 写清运行边界的完整任务包**
   - 不只是「做个首页」，而是给出：
     - 页面结构 + 状态机
     - 每个组件的 props / 交互规则
     - 异常状态（loading / error / empty）
     - 可访问性要求（focus 顺序、aria-label）
   - 附带设计稿 / Figma 链接 / 截图标注

5. **用 Playwright 截多端图对照规范反复修正**
   - 关键页面 / 关键组件在移动端 + 桌面端截图
   - 对照设计规范检查：
     - 视觉还原（颜色、字体、间距）
     - 交互行为（hover、focus、disabled）
     - 响应式断点表现
   - 发现问题 → 修 prompt → 再生成 → 再截图对比

6. **全流程工程化测试**
   - 单元测试 + 集成测试
   - E2E 测试覆盖核心路径
   - 性能审计（Lighthouse / bundle size）
   - 最终验收：视觉还原度 + 工程健壮性

## 适合场景

- 用 Codex / Cursor / Windsurf 等 AI 编程工具做前端项目
- 团队希望 AI 产出接近「正式上线」品质而非原型 Demo
- 需要建立可复用的 AI 前端工程化 SOP
