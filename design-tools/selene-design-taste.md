## 功能描述

一份从真实项目实战中凝固出来的设计审美档案与强制工作流：让 AI 给用户做任何视觉产出物（宣传页 / 落地页 / 一图流 / 控制台 / APP UI / 教程卡组）时，**先对齐用户的审美基准再动手**，而不是输出训练数据里的默认模板。核心纪律：亮色系铁律、反 AI 泔水清单、先确认风格再动手、参照范例逐像素拆解、真机尺寸验收、固定尺寸卡组生产管线、教程卡内容纪律。

### 核心特性

- **亮色系铁律**：默认禁止暗色/深色主题（局部深色如代码区可以，整体基调永远亮）
- **冻结默认模板**：深色圆角大卡片、渐变 Hero、几何无衬线标题、pill 按钮、emoji 图标、三列 feature grid、logo 墙、渐变文字——一律不得默认输出
- **先确认再动手**：交付物形态、配色、字体气质、排版参照、情绪叙事，五项确认后才开工
- **逐像素读参考**：用户给的设计稿/色卡是审美基准，签名元素必须复用
- **真机验收**：桌面预览通过不算数，按 412×915 与 360×800 两档真机尺寸各过一遍
- **卡组生产管线**：1080×1440（3:4）固定坐标 + `?card=N` 导出模式 + headless Chromium 逐卡截图 + 拼版 QA
- **教程卡内容纪律**：JTBD 反推选题、核心卖点先实证、必备避坑章、诚实边界劝退、真实部署截图嵌入循环

### 适合场景

- 给对审美有明确要求的用户做前端/视觉物料，反复被批"丑""普通""AI 泔水"想要系统性纠偏
- 小红书等平台的固定尺寸教程卡组生产
- 团队/个人想把"我认可的设计品味"沉淀成 AI 可执行的规则档案

> **复用说明**：本技能为特定用户的审美档案（凝固自 2026-08-28 ~ 09-03 五次实战与两份检讨文档）。复用时把文中的"她"读作"你的用户（或你自己）"，色板/字体/项目锚点等档案数值按自己的审美替换；方法论纪律（铁律 / Workflow / Pitfalls / Validation）可直接沿用。

**三条不可违背的铁律：**

1. **亮色系铁律**：她讨厌暗色设计，至今每个前端都是亮色系（2026-08-30 明令，已存记忆 id 33）。出方案时**默认禁止暗色/深色主题**；代码区块、夜晚场景等局部深色可以，整体基调永远亮。
2. **先确认再动手**：她说"做个 HTML/页面/前端"时，**第一件事是确认风格方向**（配色/字体/排版/情绪/叙事），有参考要参考，不默认输出。2026-08-30 检讨书把这条列为强制流程 Step 1。
3. **她的资料全部读完再动手**：她上传的设计稿/色卡/参照截图/PDF 是审美基准，逐像素读取，漏读 = 方向必翻车（两次实战教训）。

### Scope

- 单文件宣传页/落地页/一图流 HTML（项目官网、平台宣传）
- 项目控制台/Dashboard 前端（如 Mnemosyne Y2K 控制台）
- APP UI 与交互（如 Encore 洛可可卡牌）
- 网页内嵌图、教程图（禁止用 matplotlib 做 UI 图——用锤子拧螺丝的前科）
- 开源项目教程卡组（小红书系列，如「0 元基建」）：选题反推、卖点实证、避坑章与诚实劝退、她的真实部署截图嵌入——内容纪律见附录 A §9
- 设计翻新/救场：她说"丑""普通""AI 泔水"时的自查自纠与重写

### Workflow

#### 1. 冻结默认模板（Step 0，动手前默诵）

任何情况下不得默认输出这些 AI 泔水元素：深色背景+圆角大卡片、渐变 Hero 背景、几何无衬线标题（Space Grotesk/Poppins/Inter 当标题）、彩色 pill 按钮、emoji 图标、三列等宽 feature grid、"Trusted by" logo 墙、渐变文字。

#### 2. 确认风格（Step 1，必须先问）

"做 HTML"类请求先确认：① 交付物形态（一图流宣传 / 交互探索器 / 控制台 / APP 界面 / 其他）；② 配色方向与色板；③ 字体气质（衬线/无衬线/古典/几何）；④ 排版参照（杂志风/航海图/极简/复古/具体网站）；⑤ 情绪基调与叙事结构。她有成熟设计系统，给一两个词或丢参考链接就够，但**不许替她默认**。

#### 3. 逐像素读参考（Step 2）

她给设计稿/截图/链接后：放大读每个元素，列出全部视觉元素（Logo 形态/背景纹理/边框/圆角/间距/字体字号/颜色）、叙事元素（标题语气/副标结构/CTA 文案）、交互元素（hover/滚动/动效节奏）。**她的签名元素必须复用**（如月牙 Logo、手绘网格背景、左文右图 Hero、横向椭圆岛屿、圆形罗盘核心、Before/After 对比、彩色模块顶线、希腊字母+英文双语副标）——2026-08-30 第二版"色板对了排版全错"就是漏读这些的代价。

#### 4. 先框架后填充（Step 3）

第一版只给：色板 + 排版方向 + 一个 Hero 区域；她确认后再往下做；大文件分块 append 写入、末尾校验闭合。widget 在她端可能渲染失败——widget 只是加分项，**独立 HTML 文件才是交付物**（交付独立 HTML 文件链接）。

#### 5. 话术审核（Step 4）

宣传文案自检：有没有疑问句/情绪句？有没有 Before/After 对比？CTA 有号召力吗？功能有没有翻译成好处、技术有没有翻译成感受？她要的是"高号召、强情绪、多叙事"（原话 2026-08-30），同时"实事求是、不要太夸张"（2026-08-30 smithery 单）。先写"为什么"，再写"是什么"。

#### 6. 真机验收（Step 5，封存前必做）

她用手机验收（1080×2373 物理，约 **412×915 CSS px** 安卓）。**桌面预览框里自查通过不算数**——2026-09-03 Encore M0 崩塌级教训：`clamp(100px, 25vw, 148px)` 到她真机上落地 103px，五张牌缩成"五张车票"。封存前按 412×915 与 360×800 两档真机尺寸各过一遍；尺寸用真机高度占比设计，不靠小屏假设的 vw/clamp。

#### 7. 被批之后的纪律

她说丑/普通时：不辩解，问具体哪里不对，逐条领，然后重写。她给"作业"（她自己改的设计稿）时逐元素对照分析再动手。写检讨/自查报告时：她的原话 → 文档/设计稿原文 → 实际交付 → 根因 → 可执行纠正方案（数字具体到 px），五段式。

### 审美档案速查（详见附录 A）

- **配色**：亮色系一切。已验证色板：马卡龙浅蓝（`#f0f7fb`+`#6fa8dc`）、爱琴海白昼（暖白 `#F7F4EE` / 爱琴蓝 `#1E5A7A` / 月桂金 `#A8894A` / 陶土红 `#C1663E`）、赤陶橙（`#FDF8F3`+`#C4703E`+黄铜 `#B8956A`）、洛可可晨曦（浅湖蓝/淡鹅黄/珠光粉/象牙白烫金）。她预想方向：黑白/黑粉/粉白（V rk）。雷区：暗色整体主题、廉价荧光、纯黑底白字（"黑色 Word"）。
- **字体**：默认衬线（Noto Serif SC + Cormorant Garamond 是验证组合）；她点名换才换（如"这一次不要衬线体"）。等宽字体（JetBrains Mono）做标签/代码。
- **排版**：杂志/编辑风，去边框化，hairline 1px 细线分隔，大量留白，信息密度宁低勿高。衬线体自动排除全包圆角卡片。
- **图标**：一律手绘 SVG inline（圆头描边 stroke-linecap/linejoin="round"、略不规则路径、极淡填充、currentColor 随文变色），**禁用 emoji**。
- **内容纪律**：不写估算价格（平台误判推销）；域名示例用 `.love`；叙事优先于功能清单。
- **艺术风格参考库**：洛可可（华托/布歇/弗拉戈纳尔，清淡鲜明不是甜腻）、拜占庭、穆夏、浮世绘、巴洛克、爱琴海、Frutiger Aero、Y2K 亮色（亮彩+白+铬，暗色是 cyberpunk 变种不是 Y2K）——她 2026-08-31 系统问过一轮，详见附录 A。

### Pitfalls（五次实战翻车全记录）

- **默认深色模板 = 必翻车**：2026-08-28 第一版深色+圆角卡片被批"颜色好丑""完全就是 AI 泔水"；2026-08-30 Mnemosyne 控制台"Raven Terminal"暗色方案完全踩雷（"你不要每一次第一个想法就是暗色设计"）。
- **"普通"也是翻车**：不丑但平庸同样被打回（2026-08-30"不要那种普通的东西"）——她要高号召力与独特性，不要训练数据里的"默认好看"。
- **色板 ≠ 设计**：只拿色板不拆排版/叙事/交互，做出来"色板对了排版全错"。
- **Y2K 不是暗色**：Y2K 核心是亮色+白+铬；把 Y2K 做成 dark terminal 是概念错误（2026-08-30 纠偏）。
- **无视她点名的字体**：她要衬线体时第一版给了 Noto Sans SC——她说什么就是什么，别按自己默认来。
- **emoji 当图标**：风格不统一、颜色不可控、跨平台渲染差异——手绘 SVG 替换。
- **matplotlib 做 UI 图**：工具选择错误，直接写 HTML/CSS。
- **美术资源必须当主角**：她的油画画心要大面积常态亮出，不能藏在交互后（常态牌背朝外 = 画全白画）；主角层级按设计文档执行，别自己发明视觉排序。
- **手势契约**：横滑永远只浏览、单击永远只前进、放回永远不跟进入共用一个手势；多意图压进同一手势 = 致命 mode error（Encore M0 P0）。
- **夜晚 ≠ 调暗**：浅色纪律覆盖时辰系统——夜晚是"沙龙点起灯"，不是把画面压暗加黑蒙版。
- **SVG 功力不足就交规格单**：她会说"干脆矢量图我也一起做了"——美术她重画，你出精确规格（分层、尺寸、动效锚点），别硬画简陋剪贴画充数。
- **教程卡里手绘示意图 < 真实截图**：2026-09-05 Edgechat 卡 6 手绘双向箭头读不清被 QA 打回，最终用她的真实双端同屏截图替换——教程的证据位优先留给她部署后的实证截图（PIL 裁区域嵌入），手绘示意图只是没有实证时的兜底。
- **干净扁平 ≠ 氛围**：2026-09-05 Pothos 视觉地基 v1 被她判"很普通，很平淡，没有我们讨论时的朦朦胧胧像雾像雨又像风的忧郁和安静感"——情绪型项目光把玻璃拟物做干净不够，要大气氛围（雾/水光/焦散/朦胧层次）托住情绪质地。先问"这个项目读起来是什么天气"，再定质感。
- **场景级美术优先生成位图，手绘 SVG 只守图标**（2026-09 她明令"手绘svg能换成位图就尽量用位图吧"）：封面画/空镜/建筑这类主视觉，手绘 SVG 功力不够就是简陋剪贴画——用生成位图咬她给的色卡参考图（亮度帧过审再嵌）；SVG 的领地是图标与线条装饰。亮色雨夜类情绪场景：忧郁靠雾气和雨丝托，不靠压暗（Pothos 第一帧深蓝夜景被判"丑的我有点力竭了"的根因）。
- **夜晚/雨天 ≠ 压暗的又一实证**：雨夜场景做成深蓝夜景 = 翻车；"亮色雨夜"= 浅色雾气里的白房蓝顶（圣托里尼五色卡 #FDFDFF/#A5C7E0/#91B1CA/#AFB7CC/#E3CBBF，裸粉只做一处暖窗）。与"夜晚 ≠ 调暗"同一条铁律的场景扩展。

### Validation

交付前逐项确认：

1. 整体亮色系，无默认暗色主题；无 AI 泔水清单元素（深色卡片/渐变 Hero/几何无衬线标题/pill 按钮/emoji/三列 grid/logo 墙/渐变文字）。
2. 风格方向、交付物形态已与她确认；她给的所有参考资料已逐像素读完，签名元素已复用。
3. 话术通过情绪自检（疑问/对比/号召/功能译成感受），且实事求是不过度夸张。
4. 图标全部手绘 SVG inline；字体、配色与她点名的一致。
5. 已按 412×915 与 360×800 两档真机尺寸验证；美术资源是视觉主角；手势按契约分立；单文件 HTML 分块写入且 `</html>` 闭合。
6. 卡组类交付：每卡固定尺寸（1080×1440 3:4）、`?card=N` 导出模式可独立截图、headless Chromium 逐卡导出 PNG、拼版缩略 QA + 逐卡放大抽查已做（管线见附录 A §8）。
7. 教程卡组追加确认：标题/卖点与项目实际范式一致（不蹭大概念）；「免费」类核心卖点已查官方文档实证；含避坑章与诚实边界劝退卡；实证位已开家庭作业清单给她、或已嵌入她的真实部署截图并只重导受影响卡（纪律见附录 A §9）。

### 1. 配色纪律

**总纲：亮色系一切，暗色死刑。** 她原话（2026-08-30）："你不要每一次出什么设计，第 1 个想法就是暗色设计，其实我很讨厌暗色设计，你知道吗。我到目前为止的每一个前端都没有任何一个设计是暗色的，都是亮色的。"

#### 雷区

- 暗色/深色整体主题（一切项目）
- "AI 泔水色"：训练数据默认的蓝紫渐变、荧光色堆砌
- 纯黑底 + 白字（"黑色 Word"）
- 实线描金粗边框（显廉价）、廉价粉红塑料甜腻（洛可可 ≠ 塑料粉）
- 她预想中的 V rk 方向：**黑白 / 黑粉 / 粉白**（深色只允许以"黑X"对比形式出现，且是她点名的方向时才用）

### 2. 字体纪律

- 默认衬线：中文 **Noto Serif SC**，英文标题 **Cormorant Garamond**（古典衬线验证组合）。
- 她点名换才换："这一次不要衬线体了，换一个字体，你随便选吧"（2026-08-30）→ 才可用无衬线，但仍忌几何无衬线当标题（Space Grotesk 方案被打回过一次）。
- 等宽 **JetBrains Mono** 只做标签/代码/数据（细字、大写、宽字距 letter-spacing ~1.5px）。

### 3. 排版纪律（杂志/编辑风）

- **去边框化**：用 1px hairline（半透明）+ 留白 + 字号对比分隔内容，不用粗边框卡片。
- 衬线体 = 需要呼吸空间，自动排除全包圆角卡片（"全包的圆方框完全浪费了衬线体和颜色"）。
- TIP 用左侧竖线 + 斜体；大号装饰数字（42px 细衬线）代替圆圈节点。
- 信息密度宁低勿高；双层细线页面边框可以做仪式感。

### 4. 图标规范（禁 emoji，一律手绘 SVG inline）

```css
.icon-sketch path {
  stroke: var(--primary);
  stroke-width: 2.2;
  stroke-linecap: round;
  stroke-linejoin: round;
  fill: none;              /* 或极淡水彩晕染填充 */
}
```

- path 带轻微不规则（拒绝完美几何形），`currentColor` 随文变色，内联零外部依赖。
- 画不好复杂 SVG（小天使、渡鸦等）时：她重画美术，你出规格单（分层结构、尺寸、动效锚点），别硬画简陋剪贴画——"svg 画的那么简陋"是 P1 级批评。

### 5. 文案话术标准

**要**：高号召、强情绪、多叙事；疑问句/哲学句开场；Before/After 对比结构；把功能翻译成好处、把技术翻译成感受；双语副标（希腊语/法文+英文是她的调调）。

### 8. 固定尺寸卡组生产管线（2026-09-04 航图卡八张验证交付）

她要"方便截图"的成套卡片（小红书主发）时，用这套管线，**别让她自己截图**（她过去的截图尺寸全乱：1306×1377 / 1293×936 / 1734×1095）：

1. **单 HTML 多卡**：每卡 `<section class="card" data-card="N">` 包一层**固定 1080×1440（3:4）的 `.card-inner`**，内部全部绝对定位到 1080×1440 坐标系；JS `fit()` 按 `clientWidth/1080` 整体 `scale()` 适配预览。
2. **导出模式**：`?card=N` 时隐藏其他卡、容器定宽 1080px——每张卡可被独立精确截图。
3. **逐卡出图**：`chromium --headless=new --disable-gpu --hide-scrollbars --window-size=1080,1440 --screenshot=/tmp/cardN.png "file:///...index.html?card=N"`，PNG 逐张交付。
4. **位图美术抠图**（她出位图、我合成时）：PIL/numpy 色距抠 alpha（`key_out`，lo=12/hi=46 平滑斜坡，`alpha**1.15`），内容 bbox 裁剪（`crop_content`，6% pad）。
5. **QA 双保险**：全部卡拼 2×4 缩略图过一眼整体节奏 → 逐卡放大抽查细节区（设备区/表格区/中下区）→ 412 真机宽度再过一遍 → 版本封存。

### 9. 教程卡组：内容纪律与实证嵌入循环（2026-09-05「0 元基建」01 Edgechat / 02 Portkey 双卡组实战凝固）

她要"给某个开源项目出教程"（小红书卡组形态）时，在 §8 管线之上叠加这套内容纪律：

1. **选题走 JTBD 反推**：从目标人群的工作/需求反推项目价值再写教程（她原话："从他们的工作或者说需求反推项目产品再出教程"）。先答"什么人会需要这个、他们拿它干什么"，人群定了一切文案角度才有锚。
2. **范式区分红线**：教程标题/卖点必须与项目实际范式一致。实战纠偏：Edgechat 是聊天系统不是网关——她想写「免费个人网关」，纠正后标题与定位改口，网关选题换 Portkey 另起一篇。**拿不准项目是什么就先读 README 再定标题，不许蹭更大的概念。**
3. **核心卖点先实证再写**：「免费」「零成本」这类论点先查官方文档核实当前仍成立（实战：确认 Durable Objects 已进 Cloudflare 免费档——若仍收费，整套教程论点会塌）。论点先塌在写作前，别塌在评论区。
4. **必备卡结构**（8 卡验证版）：封面钩子 → 痛点 → 解法（免费额度表）→ 一笔账 Before/After（她的真实成本：2C4G ¥70/月 vs ¥0/月）→ 部署步骤 → 亮点机制 → **避坑章（写别的教程不写的坑，如 workers.dev 域名国内不可达必须绑自定义域名）** → **诚实边界劝退（她的风格签名：写明不适合谁）** + CTA + 下篇预告（系列钩子）。
5. **实证嵌入循环（教程写到哪、她部署到哪）**：
   - 初稿在对应卡留实证位，同时给她开「家庭作业清单」——标准五张：部署成功页（Actions 绿勾）、平台资源列表、自建实例界面+后台、双端同屏对比、账单 $0.00。
   - 她"交作业"后：PIL 裁关键区域（裁掉浏览器 chrome 与隐私信息）存 `assets/`，嵌进对应卡；**真实截图优先于手绘示意图**（卡 6 教训：手绘双向箭头读不清被 QA 打回，最终用真实双端同屏替换——证据力与可读性双赢）。
   - 只重导受影响的卡（`?card=N` 逐卡导出），重新拼版 QA，再封存新一版。
6. **文案口径**：「免费」必须带边界（免费≠无限，额度表给数字）；踩坑写第一人称真实经历（"我撞上过一次 migration 报错——看日志，按红字修就好"）——只有真部署过的人写得出来的话，是教程可信度的分水岭。

### 2. Encore un Sortilège de Verbe（洛可可陪伴 APP）

- 设计文档：`Encore_un_Sortilege_de_Verbe_设计文档`（v1.1 → v1.2，跨会话随她搬运，以最新版为准）。

- **手势契约（M0 血泪定型，一式一份）**：横滑=扇形整体轮转（drag 从单牌彻底拆除）；单击常态牌=焦点浮起+世界暗下；焦点态单击=翻转进入；单击背景/下滑=放回；双击中央=暗号开门。滑动永远只浏览，单击永远只前进，放回永远不跟进入共用一个手势。
- **时辰系统**：入夜不是关灯压暗，是"沙龙点起灯"——浅色纪律覆盖一切时段。
